시각 방향 4안 — 같은 문서, 극단적으로 다른 네 개의 뷰어

동일한 샘플 마크다운 문서(제목·표·코드·수식·콜아웃·위키링크·작업 목록)를 네 가지 방향의 앱 셸로 렌더링했습니다. 정답은 없습니다 — 어느 것이 "작성자의 의도대로 보인다"고 느껴지는지 반응을 주시면 됩니다. 섞는 것(예: C의 셸 + B의 본문 조판)도 가능합니다.

A

GitHub 표준

"GitHub에서 보이는 그대로" — 가장 익숙하고 예측 가능한 GFM 렌더링. 충실도의 기준선.

MD Viewer — ~/Documents/ULSOO-docs

장점: 협업자와 보는 화면이 동일, 학습 비용 0. 단점: 개성 없음, 장문 독서 피로는 그대로.

B

서재 (Paper)

"문서를 책처럼 읽는다" — 세리프 조판, 좁은 본문 폭, 중앙 정렬 제목. 크롬은 뒤로 물러난다.

MD Viewer — ~/Documents/ULSOO-docs

장점: 장문 연구 문서 통독에 최적, 인쇄물 감각. 단점: 표·코드 위주 기술 문서에서는 세리프가 이질적일 수 있음.

C

IDE 다크

"코드의 연장선에 있는 문서" — VS Code 계열의 밀도와 다크 팔레트, 하단 상태 바, 강한 신택스 컬러.

MD Viewer — ~/Documents/ULSOO-docs

장점: 코드 블록·다이어그램이 주인공인 문서에 강함, 야간 작업 친화. 단점: 밝은 도표·이미지가 많은 문서에서는 대비 관리 필요.

D

젠 미니멀

"크롬이 사라진 뷰어" — 사이드바는 아이콘 레일로 접히고, 탭은 알약형으로 떠 있으며, 화면의 90%가 본문.
