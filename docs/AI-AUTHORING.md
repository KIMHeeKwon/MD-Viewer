# AI와 함께 쓰는 마크다운 작성 지침

MD Viewer는 **LLM과의 대화로 정리한 자료를 다시 읽기 위한 뷰어**로 쓰인다.
이 문서는 그 목적에 맞게, LLM에게 "이 뷰어에서 제대로 보이는 마크다운"을 만들게 하는
작성 규약을 정리한다.

- 이 뷰어가 지원하는 문법의 **정확한 범위**와 **지원하지 않는 것**
- LLM에게 그대로 붙여 넣을 **프롬프트 블록**
- 여러 문서를 오래 쌓아갈 때의 **파일·폴더 규약**

---

## 1. LLM에게 주는 프롬프트 (복사해서 사용)

대화 끝에 "정리해 줘"라고 요청할 때, 아래 블록을 함께 붙이면 결과물이 뷰어에서 의도대로
렌더링된다.

```text
마크다운으로 정리해 주세요. 다음 규약을 지켜주세요.

[문법]
- GitHub Flavored Markdown: 표, 작업 목록(- [ ]), 취소선, 각주([^1])
- 수식: 인라인 $E=mc^2$, 블록 $$ ... $$
- 다이어그램: ```mermaid 코드 블록 (flowchart, sequenceDiagram 등)
- 코드: 언어를 명시한 펜스 블록 (```python)
- 강조 블록: > [!note] / [!tip] / [!warning] / [!important] 형식의 콜아웃
- 다른 문서 참조: [[문서명]] 또는 [[문서명|표시할 이름]] (위키링크)

[금지]
- 원시 HTML 태그 사용 금지 (태그가 <div>처럼 글자 그대로 화면에 노출됩니다)
- 이미지·파일 경로에 절대경로 사용 금지 (문서 기준 상대경로만)
- 표 셀 안에서 <br> 줄바꿈 금지 (태그가 글자로 보입니다)

[구성]
- 문서 첫 줄은 H1 제목 하나
- 제목 계층(H1 > H2 > H3)을 건너뛰지 말 것 — 개요 패널이 이 구조로 만들어집니다
- 문서가 길어지면 H2 단위로 나누어 주세요
```

## 2. 지원 문법 범위

| 기능 | 표기 | 비고 |
|------|------|------|
| 표 | GFM 파이프 표 | 셀 안 줄바꿈 불가 |
| 작업 목록 | `- [ ]` / `- [x]` | 체크박스로 렌더링 |
| 각주 | `[^1]` + `[^1]: 내용` | 문서 하단에 모임 |
| 인라인 수식 | `$E = mc^2$` | KaTeX |
| 블록 수식 | `$$ ... $$` | KaTeX, 가로 스크롤 지원 |
| 다이어그램 | ` ```mermaid ` | flowchart · sequence · gantt 등 |
| 코드 하이라이트 | ` ```python ` | 언어 명시 시 신택스 색상 적용 |
| 콜아웃 | `> [!note]` | 타입별 색상 (아래 표) |
| 위키링크 | `[[문서명]]` | 클릭 시 같은 폴더의 문서로 이동 |
| 이미지 | `![설명](그림.png)` | 문서 위치 기준 상대경로 |
| 자동 링크 | `https://…` | URL을 그냥 써도 링크가 된다 |

### 콜아웃 타입

| 타입 | 색 |
|------|-----|
| `note` · `info` 등 그 외 | 파랑 (기본) |
| `tip` · `success` | 초록 |
| `warning` · `caution` | 주황 |
| `important` · `danger` · `error` | 빨강 |

```markdown

```

## 3. 지원하지 않는 것 (LLM이 자주 넣는 것들)

| 넣지 말 것 | 이유 / 대안 |
|-----------|------------|
| `<div>`, `<br>`, `<details>` 등 **원시 HTML** | 보안상 HTML 파싱이 꺼져 있어 **태그가 글자 그대로 노출된다**. 조판이 필요하면 표나 콜아웃을 쓴다 |
| `<img src="...">` HTML 이미지 | `![설명](경로)` 마크다운 문법을 쓴다 |
| 표 셀 안 `<br>` 줄바꿈 | 위와 같은 이유로 글자로 보인다. 셀을 나누거나 내용을 표 밖으로 뺀다 |
| 절대경로 (`/Users/...`, `C:\...`) | 다른 PC에서 전부 깨진다. 상대경로만 쓴다 |
| 이모지 섹션 마커 | 개요 패널 제목이 지저분해진다 |

## 4. 문서를 쌓아갈 때의 규약

LLM 대화 산출물은 **한 편으로 끝나지 않고 계속 쌓인다.** 아래 규약을 지키면 뷰어의
개요·백링크·전체 검색이 제 역할을 한다.

**파일명**: 위키링크가 파일명으로 해석되므로, 파일명이 곧 참조 키다.
날짜나 버전을 앞에 붙이기보다 **주제를 파일명으로** 쓰고(`STT-파이프라인.md`),
날짜는 문서 안에 적는다. 파일명이 바뀌면 그 문서를 가리키던 위키링크가 끊긴다.

**문서 간 연결**: 관련 문서는 반드시 `[[위키링크]]`로 잇는다. 그러면 반대편 문서에서
**백링크 패널**로 "이 문서를 참조하는 문서들"을 볼 수 있다. 텍스트로 파일명만 적으면
이 연결이 만들어지지 않는다.

**폴더 구성**: 주제별 폴더로 나눈다. 트리 사이드바가 그 구조를 그대로 보여주고,
전체 검색(⌘⇧F)은 폴더 전체를 대상으로 동작한다.

**제목 계층**: 개요(아웃라인) 패널은 H1~H6 구조로 만들어진다. 계층을 건너뛰면
(H2 다음에 H4) 개요가 어긋나 보인다.

## 5. 결과 확인과 공유

1. 폴더를 열고(⌘O) 문서를 확인한다. 외부 편집기로 고치면 **자동으로 다시 렌더링**된다.
2. 수식·다이어그램이 깨졌다면 문법 오류다. 그 블록만 LLM에 다시 물어 고친다.
3. 남에게 보낼 때는 **HTML로 내보내기(⌘⇧E)** — 스타일·수식 폰트·이미지가 모두 들어간
   파일 하나가 되어, 받는 사람이 이 뷰어 없이 브라우저로 열어도 똑같이 보인다.
4. 인쇄·제출용은 **PDF로 내보내기(⌘E)** — 화면이 다크 테마여도 항상 흰 배경으로 나온다.
