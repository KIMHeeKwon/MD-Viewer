# ARCHITECTURE — MD Viewer 시스템 설계

> **이 문서의 자리**: 시스템이 *어떻게 만들어져 있는가*를 기술한다. 무엇으로 정했는지는
> [[DECISIONS]], 왜 그렇게 생각했는지는 [[RATIONALE]], 색·타이포 토큰은 [[DESIGN]],
> 사용법은 [[USER-GUIDE]]가 각각 단일 원천이다. 여기서는 결정의 *결과로 만들어진 구조*만 다룬다.
>
> 기준 버전: **v0.14.0** (2026-08-15 코드 실측). 코드 총 4,142줄
> (main 688 · renderer 1,755 · graph 402 · styles 921 · edit-core 52 · preload 37 · html 101 · test 186).

---

## 1. 무엇을 만든 것인가

**LLM과의 대화로 정리한 마크다운 문서를 작성자 의도대로 다시 읽기 위한 단독 실행 데스크톱 뷰어**다.
읽기가 중심이고, 편집은 켜야 나오는 보조 기능이다.

### 1.1 설계 목표 (우선순위 순)

1. **렌더링 충실도** — 수식·다이어그램·표·코드가 어느 OS에서든 **똑같이** 보인다.
2. **문서 뭉치 탐색** — 한 편이 아니라 폴더 단위로 오가며 읽는다.
3. **읽기 경험의 정숙함** — 화면에 군더더기를 두지 않는다.
4. **문서 안전** — 편집이 들어온 뒤로는 *문서를 깨뜨리지 않는 것*이 최우선 제약이 됐다.

### 1.2 비목표 (의도적으로 하지 않는 것)

| 하지 않는 것 | 이유 |
|---|---|
| 파일 생성·이름 변경·삭제 | 파일 관리 도구가 아니다 ([[DECISIONS\|D20]]) |
| 위키링크 리네임 전파 | 위와 같은 이유. 파일명이 바뀌면 링크는 끊긴다 |
| 다중 창 | 단일 인스턴스 + 탭으로 충분하다 |
| 플러그인 시스템 | 번들 크기와 렌더링 일관성을 지키기 위해 |
| 서버·계정·동기화 | 단독 실행이 전제다 ([[DECISIONS\|D7]]) |
| 마크다운 WYSIWYG | 렌더링은 단방향이다. 원문을 고치는 방식만 제공한다 ([[DECISIONS\|D21]]) |

## 2. 시스템 구조

### 2.1 프로세스 모델

Electron의 두 프로세스로 나뉘며, **권한 경계가 곧 설계 경계**다.

| | main 프로세스 | renderer 프로세스 |
|---|---|---|
| 파일 | `src/main.js` (688줄) | `src/renderer/*` (3,179줄) |
| 권한 | Node.js 전체 (fs, 대화상자, 메뉴, 네트워크) | **없음** — `sandbox: true`, `nodeIntegration: false`, `contextIsolation: true` |
| 책임 | 파일 읽기·쓰기, 폴더 스캔, 파일 감시, 메뉴, 업데이트, 네이티브 대화상자 | 마크다운 렌더링, 모든 UI 상태, 편집 계산, 그래프 그리기 |

렌더러는 **파일 시스템에 직접 접근할 수 없다.** 필요한 모든 것은 `src/preload.js`(37줄)가
`contextBridge`로 열어 둔 **22개 함수**를 통해서만 요청한다. 이 목록이 신뢰 경계의 전부다.

```
사용자 문서 (디스크)
        ▲ fs.readFileSync / writeFileSync
        │
   [ main 프로세스 ]  ← 유일하게 디스크를 만진다
        ▲ IPC (invoke / send / webContents.send)
        │
   [ preload ]  ← contextBridge로 22개 함수만 노출 (allowlist)
        ▲ window.api.*
        │
   [ renderer ]  ← 문서를 그리고 편집 결과를 "계산"만 한다
```

### 2.2 왜 Electron인가

Tauri(OS 내장 웹뷰)는 바이너리가 10배 작지만 **OS마다 렌더링 엔진이 다르다**(macOS WebKit /
Windows WebView2). 목표 1(어디서나 같은 모습)과 정면 충돌해 기각했다. Chromium을 번들하는
~120MB는 낭비가 아니라 **요건을 만족시키는 대가**로 해석한다 ([[DECISIONS\|D2]], [[RATIONALE]]).

### 2.3 모듈 지도

| 파일 | 줄 | 책임 |
|---|---|---|
| `src/main.js` | 688 | IPC 17종, 메뉴, 폴더 스캔, 파일 감시, 그래프·백링크 인덱싱, 내보내기, 업데이트 |
| `src/preload.js` | 37 | 신뢰 경계. 22개 API + 메뉴 채널 allowlist |
| `src/renderer/renderer.js` | 1,755 | 마크다운 파이프라인, 탭·트리·아웃라인·백링크, 편집, 찾기, PDF, 내보내기 트리거 |
| `src/renderer/edit-core.mjs` | 52 | **순수 함수만.** 줄 범위 교체 계산 (DOM·Electron 의존 0) |
| `src/renderer/graph.js` | 402 | 연결 그래프 — 자체 구현 힘-지향 레이아웃 + 캔버스 렌더링 |
| `src/renderer/styles.css` | 921 | [[DESIGN]] 토큰 매핑 + 앱 스타일, 인쇄 CSS 포함 |
| `src/renderer/kkobak/` | — | **KKOBAK(HKDS) 디자인 시스템** 토큰·폰트. 외부 산출물이라 직접 고치지 않는다 |
| `src/renderer/index.html` | 101 | 정적 골격 (사이드바·탭바·패널·상태 바) |
| `test/edit-core.test.mjs` | 186 | 문서 손실 방지 단위 테스트 20건 |

`edit-core.mjs`만 `.mjs`인 이유: **Node가 번들러 없이 직접 import해 테스트**해야 하기 때문이다
(패키지가 CJS 기본이라 `.js`로는 ESM import가 안 된다).

## 3. 데이터 모델

### 3.1 렌더러 전역 상태

```js
const state = {
  root: null,          // 열린 폴더의 절대경로
  rootName: '',        // 사이드바 헤더에 쓰는 폴더명
  tree: [],            // 재귀 트리 노드 배열
  tabs: [],            // 탭 객체 배열 (아래)
  active: null,        // 활성 탭의 path
  theme: 'dark',
  editMode: false,     // 기본은 읽기 전용 — 켜야 편집이 열린다
  fileIndex: new Map(),// 소문자 파일명(확장자 제외) → path — 위키링크 해석용
  treeFiles: new Set(),// 트리에 실제로 있는 파일 경로 — "트리 밖" 판정의 기준
  loose: [],           // 트리 밖에서 연 문서 (연 순서 유지)
};
```

### 3.2 탭 객체

```js
{ path, name, dir, pane,        // pane = 이 문서의 DOM 컨테이너
  source,                       // 원문 (LF로 정규화된 상태)
  original,                     // "문서를 연 시점"의 원문 — 되돌리기 기준점
  eol,                          // '\n' | '\r\n' — 저장할 때 복원
  isPdf, pdfDoc, pdfScroll }    // PDF 탭 전용
```

**`source`를 LF로 정규화해 들고 있는 이유**: markdown-it이 파싱 전에 CRLF를 LF로 바꾸고
**그 기준으로 토큰의 줄 번호를 매기기 때문**이다. 편집 계산이 같은 기준이어야 어긋나지 않는다.
파일의 원래 줄바꿈은 `eol`에 기억했다가 저장 시 되돌린다 — 오타 하나 고쳤다고 파일 전체의
줄바꿈이 바뀌면 안 되기 때문이다.

### 3.3 영속 상태 (localStorage, 9개 키)

| 키 | 내용 |
|---|---|
| `session` | `{ root, tabs[], active, loose[] }` — 재시작 시 복원 |
| `editMode` | 편집 모드 on/off (모드가 유지되는 근거) |
| `theme` · `docFontSize` · `readWidth` · `sidebarWidth` · `outlineHeight` | 읽기 환경 |
| `findCase` · `findRegex` | 찾기 옵션 |
| `autoUpdateCheck` | 자동 업데이트 확인 여부 |

**문서 내용은 절대 저장하지 않는다.** 경로만 저장하고, 복원 시 파일이 없으면 조용히 건너뛴다.

## 4. IPC 계약

렌더러가 할 수 없는 일의 전체 목록이자, 공격 표면의 전체 목록이다.

### 4.1 요청–응답 (`invoke`, 15종)

| 채널 | 역할 | 반환 |
|---|---|---|
| `folder:open` / `file:openDialog` | 폴더·파일 선택 대화상자 | 경로 또는 트리 |
| `folder:openPath` | 대화상자 없이 경로로 폴더 스캔 (세션 복원용) | 트리 |
| `file:read` / `file:readBinary` | 텍스트 / PDF 바이트 | `{content}` · `{data}` · `{error}` |
| **`file:write`** | **원본 문서 저장** | `{ok}` 또는 `{error}` |
| `dialog:unsaved` | 미저장 이탈 확인 (네이티브 2버튼) | `0`=저장 · `1`=버리기 |
| `search:project` | 폴더 전체 줄 단위 검색 | 파일별 매치 + `capped` |
| `graph:build` | 위키링크 그래프 구성 | 노드·간선·미해결 |
| `links:backlinks` | 역참조 수집 | 파일·줄 목록 |
| `html:export` / `pdf:export` | 내보내기 | 저장 경로 |
| `update:check` / `install` / `openPage` | 업데이트 | 상태 |

### 4.2 단방향 (`send`, 2종)

`watch:set`(감시 목록 동기화) · `menu:block-context`(블록 우클릭 팝업 요청).

### 4.3 main → renderer (19종)

`file:changed`(외부 변경) · `open-file`(Finder 더블클릭·argv) · `update:state` ·
그리고 `menu:*` 16종. **preload의 allowlist에 있는 채널만 렌더러가 구독할 수 있다.**

### 4.4 오류 처리 규약

**IPC는 예외를 경계 밖으로 던지지 않는다.** 실패는 `{ error: "..." }` 값으로 돌아온다.
저장 실패(권한 없음·디스크 가득)는 *일어날 수 있는 일*이고, 그때 **사용자가 방금 타이핑한
글을 잃게 두면 안 되기 때문**이다. 호출부는 값을 보고 편집창을 유지할지 결정한다.

## 5. 렌더링 파이프라인

```
원문 → markdown-it(+플러그인 5종) → HTML 문자열 → DOM 후처리 5단계 → 화면
```

### 5.1 markdown-it 구성

| 플러그인 | 출처 | 역할 |
|---|---|---|
| task-lists · footnote · texmath(KaTeX) | 외부 | 체크박스 · 각주 · 수식 |
| **`wikilinkPlugin`** | 자체 | `[[대상]]` · `[[대상\|표시명]]` → 클릭 가능한 앵커 |
| **`calloutPlugin`** | 자체 | `> [!type]` → 콜아웃. **`-`/`+` 접기 표기 해석** |
| **`srcLinePlugin`** | 자체 | 블록 토큰에 `data-src-start/end` (원문 줄 범위) 부여 |

`html: false` — **원시 HTML을 파싱하지 않는다.** 문서가 스크립트를 실행할 수 없다는 뜻이고,
LLM이 자주 넣는 `<div>`가 글자로 노출되는 이유이기도 하다 ([[AI-AUTHORING]]).

### 5.2 DOM 후처리 — **순서가 계약이다**

`renderInto()`의 다섯 단계는 순서에 의존한다. 뒤바꾸면 조용히 깨진다.

1. **펜스 속성 승격** — markdown-it은 코드 펜스의 속성을 `<pre>`가 아니라 `<code>`에 붙인다.
   블록 전체가 편집 대상이 되도록 `<pre>`로 끌어올린다.
2. **이미지 경로 재작성** — 상대경로 → 문서 위치 기준 `file://` 절대경로.
3. **Mermaid 치환** — `<pre>`를 `<div class="mermaid">`로 갈아끼우고 async 렌더.
   이때 **1단계에서 올려둔 `data-src-*`를 승계**시킨다. ①이 먼저여야 하는 이유가 이것이다.
4. **콜아웃 접기 결선** — 제목 클릭 → `collapsed` 토글.
5. **위키링크·헤딩 id·앵커 결선** — 헤딩은 GitHub식 슬러그를 id로 써서 문서 내 목차가 동작한다.

### 5.3 재렌더 전략

편집·외부 변경 후에는 **부분 갱신이 아니라 문서 전체를 다시 그린다**(`rerenderTab`).
편집으로 줄 수가 바뀌면 그 뒤 모든 블록의 줄 번호가 어긋나는데, 어긋난 매핑을 보정하는 대신
**매핑을 새로 만들어버리는 편이 단순하고 안전**하기 때문이다. 스크롤 위치는 보존한다.

## 6. 편집 서브시스템

**이 앱에서 실패의 최악을 "안 보임"에서 "문서 손실"로 격상시킨 유일한 부분**이다.
설계 전체가 그 격상에 대한 대응이다.

### 6.1 핵심 원리 — 역변환하지 않는다

화면의 `<p>`를 마크다운으로 되돌리는 것은 불가능하다. 대신 **markdown-it이 이미 알고 있는
줄 범위**(`token.map = [시작, 끝)`)를 HTML에 심어두고, 편집은 **원문의 줄 범위를 갈아끼우는
문자열 연산**으로 환원한다.

```
화면의 이 문단  ──data-src-start/end──▶  원문 2~3줄  ──replaceBlock──▶  새 원문 전체
```

### 6.2 계층

| 계층 | 위치 | 성질 |
|---|---|---|
| 계산 | `edit-core.mjs` | **순수 함수.** 테스트로 방어 |
| 조립 | `renderer.js`의 편집 절 | 편집창 수명, 저장 정책, UI 상태 |
| 쓰기 | `main.js` `file:write` | 실제 디스크 접근 + 감시 되먹임 억제 |

`edit-core.mjs`의 6개 함수: `detectEol` · `normalizeEol` · `applyEol` · `trimBlankTail` ·
`sliceBlock` · `replaceBlock`.

> **`trimBlankTail`이 필요한 이유**: 리스트 토큰의 `map`은 블록을 끝내는 **빈 줄까지 포함**한다
> (예: 리스트가 4~5줄인데 `map`은 `[4,7)`). 그 빈 줄은 블록 사이의 간격이므로 편집 범위에서
> 빼지 않으면, 저장하는 순간 **리스트가 다음 문단을 삼킨다.**

### 6.3 두 가지 편집 모드와 저장 정책

| | 인라인 블록 편집 | 소스 모드 |
|---|---|---|
| 진입 | 편집 모드에서 블록 **더블클릭** | `⌘⌥S` 또는 상태 바 `소스` |
| 범위 | 블록 하나의 원문 | 문서 전체 원문 |
| 저장 | **자동** (편집창 이탈 시) | **명시** (`⌘S`) |
| 실패 파장 | 블록 몇 줄 | **문서 전체** |

**자동 저장을 고른 것은 편의가 아니라 안전 설계다.** 미저장 상태가 없으면 탭 닫기 경고·세션
복원 시 미저장분 처리·크래시 복구가 *구현 대상이 아니라 존재하지 않는 것*이 된다
([[DECISIONS\|D22]], [[RATIONALE]]).

### 6.4 더티 봉인 (소스 모드)

명시 저장을 택한 대가로 미저장 상태가 되살아난다. 그것을 **한 화면 안에 가둔다.**

> 소스 모드를 벗어나는 **모든 경로 — 토글 해제 · 탭 전환 · 탭 닫기 · 편집 모드 끄기 —
> 가 `exitSourceMode()` 하나로 모인다.** 출구가 하나라서 "어떤 경로로 나갔을 때만 확인을
> 안 하는" 종류의 버그가 생길 수 없다.

미저장이면 네이티브 2버튼 대화상자(`저장` / `변경 버리기`, 기본값 = 저장)로 확정한다.
`window.confirm`을 쓰지 않은 이유는 버튼 라벨을 정할 수 없어 **"취소 = 버리기"라는 위험한
매핑**이 되기 때문이다 ([[DECISIONS\|D40]]).

### 6.5 진입 제어 — 왜 모드가 필요한가

**더블클릭은 이미 "단어 선택"이다.** 읽으면서 인용하려고 단어를 긁는 동작과 겹치므로,
모드 없이 편집을 얹으면 우발적 편집이 상시로 일어나고 자동 저장이라 즉시 디스크에 박힌다.
그래서 **편집 모드가 꺼져 있으면 더블클릭은 종전대로 단어 선택**이고, 켜져 있을 때만 편집이
열린다. 호버 연필 버튼은 [[DESIGN]] 금지 3(본문에 UI 크롬 침범)에 막혀 기각됐다.

### 6.6 메모 (콜아웃 주석)

블록 아래에 `> [!note]-` 콜아웃을 끼워 넣는다. **삽입 전용 함수가 없다** — 블록을
`본문 + 빈 줄 + 메모`로 교체하면 한 번의 쓰기로 삽입이 된다.

진입점 두 개가 `insertMemoAfter()` 하나로 합류한다:
- **우클릭 → 메모 달기**: 그 블록 원문은 손대지 않는다
- **편집창에서 `⌘⇧M`**: 고치던 내용까지 함께 저장한다

`-` 표기로 넣어 **접힌 채로** 들어간다. 메모가 쌓여도 읽기 흐름을 끊지 않으면서
"여기 메모가 있다"는 표식은 남기기 위해서다 ([[DECISIONS\|D44]]).

### 6.7 되돌리기

`tab.original`(문서를 연 시점의 원문)이 전부다. 탭이 이미 원문을 들고 있었으므로 새로 만든
것이 거의 없다. **디스크 스냅샷도 `.bak`도 없다** — 백업의 진짜 방어선은 앱이 아니라 볼트
바깥(git·Time Machine)에 있어야 한다고 판단했다 ([[DECISIONS\|D23]]).

## 7. 파일 감시와 되먹임 억제

`chokidar`가 열린 탭의 파일을 감시한다(`awaitWriteFinish` 150ms). 외부 편집기에서 저장하면
**스크롤 위치를 유지한 채** 자동 재렌더한다.

여기에 편집이 들어오면서 **되먹임**이 생겼다 — 앱이 쓴 저장을 감시자가 외부 변경으로 오인한다.

```
renderer가 저장 ─▶ main이 write (경로를 selfWrites에 기록)
                        └▶ chokidar change 감지
                              └▶ 1.5초 내 자기 쓰기면 삼킨다  ← 억제
```

**억제가 없으면 무엇이 깨지는가**: `onFileChanged`는 `tab.source`뿐 아니라 **`tab.original`도
갱신**한다(남이 고친 것까지 되돌리면 안 되므로). 자기 저장에 그 처리가 걸리면 **되돌리기의
기준점이 밀려 기능이 무력화**된다.

소스 모드로 편집 중일 때 외부 변경이 오면 **재렌더하지 않고 상태 바 알림만** 한다 —
쓰던 내용이 사라지기 때문이다 ([[DECISIONS\|D39]]).

## 8. 문서 탐색

### 8.1 트리와 "따로 연 문서"

앱은 오래 **"열린 폴더 하나 = 전체 맥락"**이라고 가정했고, 그래서 폴더 밖 파일을 열면
읽는 문서가 사이드바 어디에도 없는 상태가 됐다. 지금은 두 맥락을 분리한다.

| 영역 | 내용 |
|---|---|
| **따로 연 문서** (트리 위) | `treeFiles`에 없는 문서만. **비면 통째로 숨는다** |
| 폴더 트리 | 절대 흔들리지 않는다 |

`refreshLoose()`가 두 조건으로 목록을 스스로 정리한다 — 탭이 닫혔거나, 폴더를 열어 트리 안으로
들어왔으면 목록에서 빠진다. 세션에도 저장되어 재시작 시 복원된다 ([[DECISIONS\|D30~D32]]).

### 8.2 위키링크 해석 (Obsidian 규칙)

`[[문서명]]`은 파일명(확장자·대소문자 무시)으로 해석한다. 후보가 여럿이면:

1. **같은 폴더**에 있는 것 우선
2. 없으면 **경로가 가장 얕은** 것
3. 그래도 같으면 사전순

그래프에서 동명 파일은 `이름 (폴더)`로 구분해 표시한다.

### 8.3 아웃라인·백링크

- **아웃라인**: H1~H6 계층. 스크롤에 따라 현재 위치를 추적한다.
- **백링크**: main이 폴더 전체를 훑어 현재 문서를 `[[...]]`로 참조하는 곳을 줄 단위로 모은다.

두 패널은 사이드바 하단에서 탭으로 전환되며 높이는 드래그로 조절된다.

## 9. 연결 그래프

`d3-force` 같은 외부 의존성 없이 **402줄로 자체 구현**했다(번들 크기·오프라인 요건).
캔버스에 그리고 전체 화면 오버레이로 띄운다.

### 9.1 힘 모델

| 힘 | 값 | 비고 |
|---|---|---|
| 반발력 | `6000 + 420n` | 노드 수에 비례해 키운다 |
| 간선 길이 | `min(240, 70 + 9√n)` | 조밀도에 따라 늘어난다 |
| 탄성 | `SPRING = 0.02` | **연결 수로 정규화** — 허브가 이웃을 끌어당겨 뭉치는 것을 막는다 |
| 중력 | `GRAVITY = 0.012` | 무게중심으로 모은다 |
| 감쇠 | `DAMPING = 0.82` | |

### 9.2 두 가지 안정화 장치

1. **운동량 상쇄** — 매 틱 평균 속도를 빼서 그래프 전체가 한쪽으로 흐르는 것을 막는다.
   (탄성을 연결 수로 정규화하면서 작용·반작용이 깨진 것을 보정한다. 실측 Δx=Δy=0.0px)
2. **알파 냉각** — `alpha *= 0.977`, 0.002 아래면 정지. 무한히 떨리지 않는다.

라벨은 노드 원을 씨앗으로 한 충돌 회피로 배치하고, 간선 투명도는 간선 수에 따라
`max(0.14, min(0.5, 80/edges))`로 조절한다.

## 11. PDF 서브시스템

Chromium 내장 뷰어(iframe)를 쓰다가 **PDF.js 직접 렌더링으로 교체**했다. 내장 뷰어의
회색 UI는 브라우저가 그리는 영역이라 **원리적으로 스타일링이 불가능**했기 때문이다.

교체의 부수 효과가 컸다 — 캔버스 위에 **텍스트 레이어**를 얹을 수 있게 되면서 텍스트 선택과
`⌘F` 검색이 가능해졌다. 내장 뷰어를 유지했다면 불가능한 확장이었다 ([[RATIONALE]]).

툴바: 페이지 이동(`◀ ▶`) · **번호 직접 입력** · 확대/축소(40~300%) · 폭 맞춤.
스크롤에 따라 현재 페이지를 추적하되, **입력 중에는 덮어쓰지 않는다**(명시적 이동과 잘못된
입력 복구는 예외 — `syncPdfPageInput(force)`).

## 13. 업데이트

`electron-updater` 기반. **OS별로 동작이 다르고, 그것이 하드 제약이다.**

| 설치 형태 | 동작 |
|---|---|
| Windows(exe) · Linux(AppImage) | 자동 내려받기 + 재시작 설치 |
| **macOS(dmg) · Linux(deb)** | **알림만** |

macOS가 자동 설치되지 않는 이유는 Squirrel이 **코드 서명된 앱만** 허용하기 때문이다.
서명이 없으면 거부되므로 알림 후 수동 교체 방식을 택했다 ([[DECISIONS\|D17]]).

## 14. 빌드·릴리스 파이프라인

```
소스 → esbuild 번들 → renderer-dist/ → electron-builder → 설치 파일 → GitHub Release
```

### 14.1 두 개의 함정과 그 대응

**① `renderer-dist/`는 gitignore 대상이다.**
CI 체크아웃에 존재하지 않으므로 패키징 전에 반드시 `npm run bundle`을 돌려야 한다.
이것이 빠져 **v0.1.0~v0.3.2까지 6개 릴리스가 렌더러 없이 나갔다.** 설치본은 스타일·스크립트
없는 뼈대 HTML만 보여줬다 ([[FAILURES]] Active Rule 2).

**② 매트릭스 병렬 빌드의 릴리스 경합.**
3개 OS 러너가 동시에 "없으면 만든다"를 수행해 같은 태그에 릴리스가 둘로 갈라졌다(TOCTOU).
설정으로는 원자적이 되지 않아, **`create-release` 선행 잡**이 릴리스를 만들고 패키징 잡들은
`needs`로 대기하도록 제어 흐름을 바꿨다 ([[FAILURES]] Active Rule 1).

### 14.2 현재 워크플로 순서

`npm ci` → **`npm test`** → **`npm run bundle`** → `electron-builder --publish always`

테스트가 패키징 앞에 있는 이유는 **문서를 깨뜨리는 계산이 배포물에 들어가는 것을 막기 위해서다**
([[DECISIONS\|D29]]).

산출물: macOS(dmg·zip, arm64) · Windows(nsis exe) · Linux(AppImage·deb).

## 15. 검증 전략

실패의 파장에 따라 세 층으로 나눈다. **검증 강도는 기능의 크기가 아니라 실패의 파장에 맞춘다.**

| 층 | 수단 | 무엇을 잡는가 |
|---|---|---|
| 1. 단위 | `node --test` (20건) | **문서 손실.** 줄 계산의 엣지 케이스 — CRLF 왕복, 파일 끝 개행, 줄 수 증감, 범위 초과, 실제 토큰과의 왕복 |
| 2. GUI | **CDP** (원격 디버깅 9222 + WebSocket) | 상호작용·상태 전이. `localStorage`에 세션을 심어 원하는 상태를 재현한다 |
| 3. 배포물 | `app.asar` 내부 확인 + 설치 후 실행 | **개발 모드 성공은 배포물 성공의 증거가 아니다** |

보조 수단으로 **AppleScript 접근성 API**를 쓴다. 네이티브 시트·팝업 메뉴는 CDP로 누를 수
없기 때문이다. macOS에서 부모 창이 있는 대화상자는 별도 창이 아니라 **`window 1`의 sheet**로
붙는다는 점이 함정이었다.

> **이 프로젝트에서 "검증 불가"라는 판정이 두 번 틀렸다.** 처음에는 GUI 검증을 "화면 기록
> 권한이 없어 불가"로 분류했다가 CDP로 뚫었고(그때 오래 잠복한 버그가 드러났다), 다음에는
> 네이티브 대화상자를 "CDP로 불가"로 분류했다가 접근성 API로 뚫었다. 공통 구조는
> **도구가 없어서가 아니라 접근 경로를 한 겹만 보고 단정한 것**이다 ([[RATIONALE]]).

### 15.1 개발 인스턴스와 설치본의 공존

```bash
npx electron . --remote-debugging-port=9222 --user-data-dir=<임시 프로필>
```

`--user-data-dir`로 프로필을 격리하면 단일 인스턴스 잠금을 피해 **설치본을 끄지 않고**
개발 인스턴스를 동시에 띄울 수 있다.
